## 🚀 快速上手

1. 双击 **`CeraBeads 拼豆图纸生成器 1.0.0.exe`**（打包版，**不用装 Python**）
2. 把图片拖进窗口 → 调尺寸（宽/高）和颜色数 → 点顶部的「**生成图纸**」
3. 满意后点顶部的「**批量导出**」，勾上要的成品（PNG / 纯净版 / JPG / 打印 PDF / 用量 CSV）→ 选个文件夹，一次全出

> 源码方式运行（装了 Python 3.10+ 的话）：`pip install -r requirements.txt` 然后 `py -3 gui.py`；
> 便携运行库方式：双击 `启动.bat`（优先用同目录 `runtime\`，其次系统 Python）。

## 🔧 算法说明（都在本机算，不联网、不用 AI）

1. **优化模式（自己选，软件不替你做判断）**：三选一，默认「通用」——
   - **通用**：不做任何专项处理，整格取线性光平均色——最忠实、最稳，照片/线稿都可用。
   - **图片优化（照片首选）**：先做一次小半径双边滤波（磨掉传感器噪点 / JPEG 块效应，**保住边缘**），再按「格内主导色引导的加权平均」取色——既保层次，又不会把边缘两侧混成灰边。
     实测同一张风景照（72×78 格）：**边缘格正确率 47.8% → 81.2%**（几乎不再冒出原图没有的灰边），纯度 81.1% → 82.8%，色号 61 → 62。
   - **动漫优化（线稿/卡通首选）**：先用 Sobel 找出抗锯齿过渡像素、把它们从「主导色投票」里剔除，再按格取主导色——轮廓不会被过渡色拉向中间调。
     实测同一张线稿（60×66 格）：纯度 90.1% → 95.1%、重建色差 5.936 → 5.731、**色号 41 → 7**（色块最干净），边缘格正确率 91.0% → 96.7%。
   - 想手动指定取色方式也行：「取色方式」= 跟随优化模式 / 照片优化 / 平均色 / 主导色。
   - 四个指标口径：**重建 ΔE**＝把图纸色号铺回原尺寸、逐像素跟原图比 CIEDE2000（越小越像）；**纯度**＝ΔE<10 的像素占比；**边缘格正确率**＝跨边界格子里「选中的色离最近那一侧真实色 ≤10」的比例（越大越不出灰边）；**色号数**＝用了几种豆子。
2. **全分辨率处理，绝不偷偷缩图**
   - 整幅原图参与取色：大图滤波、分离度统计都改成**按块计算**，不会因为图大就先缩小再算。
   - 输出也一样：超大图纸改用**逐行压缩的流式 PNG** 写出，照样全尺寸成功（不再弹「图太大先调小一点」）。只有 JPEG 编码器有单边 8000px 的硬上限，超了会按上限出一张分享图并在提示里注明。
3. **导入即给最佳格数**：按图片尺寸默认取「每格约 9 个原图像素」这个区间（上限受「最大格数上限」，默认 104 格），不够再加。
4. **默认不改图**：限制颜色数、自动去掉背景、清理碎点、叠加原图对照——四项默认**关闭**。
2. **统一相近色（防伪杂色）**：量化后加一层 4 邻域一致性（ICM）：只有当“邻居在用的某个色号”与本格色号**几乎一样（ΔE ≤ 3）**时，才把本格统一成邻居那个；所以**只会合并近重复色号，绝不引入新色号**。合成用例（两个 ΔE 0.8 的相近色）实测一次统一 **125 格**；真实照片上改动 31 格、用色数“只减不增”。
3. **匹配**：sRGB → CIELAB → **CIEDE2000** 最近色（实现用 Sharma 标准 9 组测试数据校验，最大误差 **0.000042**）。
4. **背景**：取边框颜色为背景色，与它相近且与边框连通的区域判为背景（形态学重建式洪水填充，无需 OpenCV）。
5. **限色**：超过设定色数时，保留用量最多的 N 色，其余并入最近的保留色。
6. **碎点清理（第二道防线）**：把小于 N 格的连通小色块并到相邻最多的颜色，默认关（打开后建议 N=3）。
7. **渲染**：PIL 绘制格子/色号（色号颜色按 WCAG 对比度自动选深/浅）、每 10 格红线、坐标刻度、底部用量清单。

## ❓ 常见问题

**Q：exe 打不开 / 杀软报毒？** 单文件 exe 首次启动会解包，慢几秒属正常；未签名 exe 可能被
SmartScreen 提示，点「更多信息 → 仍要运行」即可。极个别精简系统缺 `VCRUNTIME140.dll`，
装一次 VC++ 运行库即可。

**Q：图纸太大打印不清楚？** 把「每格像素」调大到 60–120（现在上限 256），或者少画几格；
整张图超过 10000 像素见方 / 1 亿像素时软件会拦住（防止渲染爆内存），这时改用 PDF 分页打印。

**Q：想要更省豆子？** 打开「限制颜色数」把滑杆拉小（例如 20），或者把尺寸调小。

**Q：能换成别的色卡品牌吗？** 内置 11 套（MARD 221/291、COCO 291、漫漫 278、咪小窝 290、盼盼 289、优肯 174/C197/M221/418）；色卡就是 `config/*.json`（字段 code/hex/rgb/group），照格式加一份就会出现在下拉里。

- **超分评估结论（没做专版）**：小图放大确实有用，但**AI 超分并不优于经典 Lanczos**——同一张照片，Lanczos 与原图的色号一致率 92.2%，EDSR 91.0%、ESPCN 88.8%、FSRCNN 87.8%（不放大只有 84.1%）；线稿上 FSRCNN 92.9% 略胜 Lanczos 90.3%。三个模型的共同问题是"看起来更锐 ≠ 每格取色更准"，而代价是 38 MB 模型 + 最高 20 倍耗时。所以把便宜有效的「Lanczos 先放大」内置，不单独做超分版。

**v1.1.0**
- 新增「**优化模式**」三选一（**通用 / 图片优化 / 动漫优化**），由用户自己选，软件不再替用户判断：图片优化 = 双边滤波去噪 + 主导色引导加权平均（照片边缘格正确率 47.8%→81.2%）；动漫优化 = 边缘像素剔除 + 主导色（线稿纯度 90.1%→95.1%、色号 41→7）。
- **不再偷偷缩图**：所有取色都在整幅原图上做（大图改为分块计算），质量不再被"省时间"牺牲。
- **不再拒绝大图**：超大图纸改用流式 PNG 逐行写出，全尺寸也能成功（去掉了"图太大，先调小一点"的弹窗）。
- 默认值：最大格数上限 **104**；导入图片时按尺寸自动给最佳格数（每格约 9 个原图像素）。
- 「取色方式」改为 跟随优化模式 / 照片优化 / 平均色 / 主导色。

**v1.0.2**
- 新增「**照片优化**」取色（默认「自动」在照片上就用它）：以格内主导色为基准做加权平均，保层次而不出灰边。三张样图实测脏边 ΔE 分别 **10.30→7.15 / 6.22→3.71 / 4.77→3.20**，重建色差在两张图上同时下降；线稿用色数 41→11。
- **默认值改成“不改图”**：限制颜色数、自动去掉背景、清理碎点、叠加原图对照——四项默认全部**关闭**（颜色数滑杆随之置灰）。
- 取色方式下拉从 3 项变 4 项（自动 / 照片优化 / 平均色 / 主导色）。

**v1.0.1**
